Coral bleaching: data cleaning and preprocessing¶

Purpose. Prepare a reproducible matrix of environmental measurements for a subsequent principal component analysis (PCA). The research question concerns environmental patterns associated with coral bleaching severity. This report covers cleaning and preprocessing only. No PCA, component selection, prediction, or group-effect analysis is performed.

The unit of observation is a sampling event identified by Sample_ID. The workflow reads coral.csv, documents quality checks and exclusions, and writes derived files to processed/. Identifiers, outcomes, dates, locations, and missingness flags remain separate from the environmental feature matrix.

1. Sources and reproducibility¶

The implementation consolidates the supplied coral_eda_cleaning_preprocessing.ipynb, coral_data_cleaning_summary.md, and data_dictionary.md. The supplied coral_pca_ready.csv was reviewed as a previous export. The downstream coral_pca_analysis.ipynb was inspected for input expectations; its analyses are outside this report's scope. These original files are preserved.

The raw file contains 41,361 substrate records and 62 columns. Its SHA-256 fingerprint matches the one recorded in the original cleaning notebook. The original dictionary defines variable meanings and units; it is retained alongside a generated column-role audit.

Run the notebook from the project folder using the versions in requirements.txt, or run python scripts/execute_notebook.py for a fresh-kernel execution and HTML reading copy. All reusable logic is imported from coral_pipeline; no cleaning functions are defined here.

2. Missing-value markers, data types, and validity¶

The source uses nd (no data). These text markers conceal missing observations and make numeric columns load as text. Surrounding whitespace is stripped, case-insensitive nd markers become missing values, and documented numeric fields are converted explicitly. Unexpected numeric tokens cause an error rather than being silently discarded.

Identifiers and date parts must contain complete integer values. Recorded percentages, coordinates, nonnegative physical quantities, and Kelvin temperatures are checked against their basic valid ranges. Negative temperature anomalies remain valid. No unit conversion is introduced; the dictionary's windspeed unit requires verification before physical interpretation.

3. Consolidating substrate records into sampling events¶

Several records describe the same event but different substrates. Treating these records as separate observations would give repeated events additional weight. Before aggregation, the implementation requires every retained environmental field, date, location, identifier, and descriptor to agree within Sample_ID, including missingness. Conflicts stop execution.

Substrate_Name and Percent_Cover cannot each be represented by one value per event. They are preserved in a separate coral_substrate_records.csv table for the final cohort, linked by Sample_ID, rather than averaged or assigned an arbitrary first value. The original decision to average differing bleaching percentages within an event is retained and audited below. This unweighted mean assumes the substrate records provide equally relevant bleaching summaries; no defensible alternative weights are supplied. Exact duplicate records, if present, are removed before this mean is calculated.

Different sampling-event IDs remain distinct even when all non-ID values match. One row per event prevents substrate repetition; it does not establish independence among repeated surveys at the same site.

4. Defining the cohort and preserving interpretation fields¶

The original research design compares bleaching-severity groups. Events without an observed Percent_Bleaching are therefore excluded, and outcomes are never imputed. Although PCA itself does not require outcomes, this restriction preserves the original requirement for observed outcomes; the additional period restriction is applied below. It can affect representativeness and must be acknowledged in subsequent reporting.

The existing cut-points are retained: Low 0–10%, Moderate >10–50%, and High >50–100%. The source Bleaching_Comments explicitly contains Mild (1–10%), Moderate (11–50%), and Severe (>50%) code descriptions. Low additionally includes recorded zeros. These are fixed study definitions rather than thresholds optimised using environmental measurements. Some percentages are averages derived from codes, so they should not all be treated as equally precise continuous measurements.

ISO dates must parse and agree exactly with their year, month, and day fields. The concentration on particular days in the original audit suggests limited day precision; retain the recorded dates and prefer year and month for later interpretation. Dates and coordinates are not inputs.

4.1. Sampling-period restriction: retain 1998 onward¶

Events sampled in 1997 or earlier are excluded. The lower boundary is inclusive: a sampling year of 1998 is retained. The ISO sampling date must agree with Date_Year. This requested study-period restriction is applied to labelled sampling events before feature selection, missingness exclusion, imputation, power transformation, or scaling. Consequently, fitted preprocessing statistics describe only the eligible period.

The exclusion table records event IDs and dates. The raw data remain unchanged; the final cleaned table, standardised matrices, and interpretation sidecar all use the same restricted cohort.

5. Selecting environmental inputs¶

The feature set contains continuous environmental measurements and environmental counts. Percent_Bleaching and its group are outcomes; IDs, dates, and geographic coordinates are interpretation fields. Categorical labels and free-text comments, including comments describing outcome derivation, are retained in the combined CSV as metadata. They are excluded only from the PCA feature matrix. Nominal labels are not assigned artificial numeric scales.

In particular, Exposure is excluded from the feature matrix. The dictionary describes “Sometimes” through a narrow exposure window and cyclone-season conditions, rather than as a numerical midpoint between sheltered and exposed. No ordinal or one-hot encoding is introduced. The earlier notebook noted that pooled exposure comparisons were sensitive to data-source composition; source and exposure labels are preserved in both the combined CSV and the metadata sidecar.

Constant features carry no variance and are excluded from PCA inputs, while their original values remain in the combined CSV. The original near-duplicate threshold, absolute Spearman correlation ≥ 0.999, is retained; the earlier column in source order is kept. The near-duplicate column also remains in the combined CSV in original units, outside the PCA input list. Rank correlation this high indicates near redundancy, not numerical equality. Other correlated environmental families remain to preserve the original feature weighting.

The original-unit cleaned table contains these imputed values for the 35 selected inputs, not the unaltered measurements. 8. Selective transformation and standardisation¶

The original workflow transforms inputs with absolute sample skewness > 0.75 using Yeo–Johnson, which accommodates zeros and negative anomalies, then standardises every input. Other inputs are standardised directly. This retained choice reduces the influence of long tails and different measurement scales. Normality is not a prerequisite for PCA, and this transformation does not guarantee normal data or eliminate influential observations.

If a direct power fit is unstable, median/IQR scaling is attempted before fitting. The fitted power, initial rescaling, and any numerical fallback are recorded per feature. A final standardisation uses population standard deviation (ddof=0). The saved fitted state includes medians and transformations in the exact feature order.

Thirty-one inputs receive Yeo–Johnson transformation. Cyclone_Frequency, Windspeed, SSTA, and SSTA_FrequencyMax are standardised directly. The same skewness rule is refitted on the retained period, so Cyclone_Frequency now falls below its threshold. Five temperature or climatology columns and Turbidity require the recorded rescaling step. Some inputs retain skew, particularly those with a large concentration at zero; no further distributional transformation is introduced.

Fitting scope and leakage. This is a descriptive preparation of the retained 1998-onward cohort. Outcomes, groups, and comments are never used to fit feature transformations. Outcome availability determines cohort membership, as documented above. For any subsequent prediction evaluation, split sample-level data by site (and by time if forecasting) before fitting feature selection, imputation, transformations, scaling, or PCA. Fit each stage only on the training fold and apply the fitted state to held-out observations. Do not use this globally fitted matrix to claim unbiased predictive performance. The dictionary also describes thermal summaries over the full historical period; their temporal availability needs review before prediction.

9. Final tables and validation¶

The original-unit cleaned table and standardised table contain the same events in the same order, preserving all 60 source columns that have a sample-level meaning, plus the bleaching group and depth-missingness flag: 62 columns in total. Of these, 35 are processed environmental inputs and 27 are metadata fields. A numeric-only matrix contains exactly the environmental columns. Its row order matches both the combined table and the metadata sidecar. Read the feature list from the exported metadata rather than selecting every numeric column: IDs, outcomes, dates, coordinates, the depth flag, and excluded environmental measurements are numeric too. Comments and categories remain readable text; preserving them does not make them PCA inputs.

Readiness checks require sampling years from 1998 onward, finite numeric inputs, nonconstant columns, near-zero means, unit population standard deviations, consistent groups and dates, unique event IDs, and row alignment. Additional checks verify preservation of all sample-level source columns and unchanged metadata values between cleaned and standardised outputs. These checks establish numerical readiness without fitting PCA.
